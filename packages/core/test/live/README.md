# Live tests: @kasten/core against the real Stalwart

```sh
./kasten dev up
pnpm --filter @kasten/core test:live
```

These tests run `@kasten/core` from Node against the running dev stack, on its published ports. They read the stack's addresses and credential file paths from `.kasten-dev/state.json` (or `$KASTEN_DEV_DIR/state.json`). Before any test runs, `global-setup.ts` checks that the state file exists, that Stalwart answers on HTTP, SMTP and IMAP, that the outbox answers and that the admin API key works. If any check fails, the run stops with the reason. No test is skipped, so a missing stack never looks like a pass.

They need Node 24, the repository's dev dependencies and `openssl` on the `PATH` (for a real opaque-signed S/MIME message).

## Their footprint on the shared stack

- Each file creates its own accounts (`core-live-<name>-<random>@kasten.test`) and OAuth clients through the admin key, and destroys them afterwards. No test uses `you@` or `sam@`, and none changes the dev client `kasten-web`.
- Every external recipient is a `.test` address. Stalwart relays it to the outbox (Mailpit); the send tests delete what they find there.
- **Outbound budget.** The stack allows 100 outbound recipients a day for the whole server. One run of `send.live.ts` uses 8.
- **SMTP pacing.** Stalwart allows 5 connections a second from one address, shared by every user of the stack. The SMTP helper retries a refusal before DATA and paces batches.
- The send-limit test sends one 38 MB message and stores its 52 MB Sent copy.
- The upload-quota test uploads 100 MB to its own account (two 50 MB uploads, over the 91.2 MB quota), waits for the 5-minute quota window to end (up to 5 minutes), then sends.
- `limits.live.ts` uses one throwaway account (`core-live-limits-*`) and one `Email/import` upload.
- The kasten.test domain has a catch-all, so a test must never send to a made-up local address: it would land in `you@kasten.test`.

The live tests and `tests/integration/` share Stalwart's anonymous HTTP limit of 100 requests per 60 seconds per IP address. If one suite starts within a minute of the other, OAuth sign-ins can fail with HTTP 429. Wait a minute between the two suites.
